## Operational findings

- **Concurrent version creates return 409.** `create-version` retries 409 with backoff;
  release and reset share the `agent-deploy` concurrency group, PR runs are serialized per PR.
- **Parallel evals interfere.** Running several 40-row evals against the agent at once
  produced failed/empty responses (throttling). Run one eval at a time, concurrency 3;
  `run_eval.py` retries each row up to 3× and records the service error.
- **Transient DNS/connection errors** on client networks: connection retries in
  `foundry_agents._request`, Search fetches and the OpenAI client (`max_retries=8`).
- **Judge strictness on refusals.** A model that correctly declines a red-team request but
  quotes the injected text ("APPROVED BY FDA") must not be scored as a defect; the safety
  grader ignores declining sentences.
- **Eval calibration.** Baseline: facts recall ≈ 0.97, groundedness mean ≈ 4.7, 0 safety
  defects. The "concise" break prompt drops to ≈ 0.85 facts recall (14/30 answers miss a key
  fact; mean 66 vs 201 words) → gate threshold 0.90. The LLM completeness judge is lenient
  on short answers, so the deterministic required-facts grader is the decisive metric.
- **Fail-closed proven** in unit tests (`tests/unit/test_gate.py`): missing metric, error
  rate, row mismatch and partial results all fail.
- **Guardrail blocks inside a hosted agent:** a Prompt Shields / content-filter rejection surfaces in Agent Framework as `ChatClientContentFilterException`. Unhandled, the hosted agent answered "insufficient evidence", hiding the guardrail. The middleware now converts it into an explicit refusal (`refusal_reason: guardrail_content_filter`, span attribute `clinical.guardrail_blocked`).
- **Cloud judges run as the submitter.** Foundry cloud evaluators call the judge deployment as the principal that *submits* the eval run, not as the project identity. The first CI run returned `401 PermissionDenied` on every judge row, and the gate failed closed. Fix: the CI candidate identity gets **Cognitive Services OpenAI User** on the Foundry account (`infra/rbac.tf`). It worked locally only because the deployer already had that role.
- **Custom code evaluators need an additional permission.** OpenAI User does not grant `Microsoft.CognitiveServices/accounts/OpenAI/evals/write`. The native code-evaluator path failed with `PermissionDenied` until an account-scoped evaluation read/write role was granted. Terraform now gives only these two data actions to candidate/deployer identities; promote access is unchanged.
- **Keep the Action's default response mappings.** A global response-text override made groundedness use the answer itself as context and return misleading passing scores. The default groundedness mapping includes the actual retrieved tool output. Mixing `messages` with `query`/`response` mappings is rejected by the service.
- **Cloud code sandbox constraints matter.** Regex helpers use `re.search` with the same patterns rather than explicit `re.compile`, which the Python-grader validator rejects as a forbidden `compile` call. Generated graders contain only the required pure functions and standard-library imports; they do not read files or call the network.
- **Uniform input columns are required.** Missing array-valued fields became empty strings in the native custom-code data source. The adapter supplies empty arrays for inapplicable facts/source/safety fields and validates all output rows. The preview Action has no run-ID outputs, so collection uses its uniquely named dataset plus exact agent/version and row markers, never the latest run.
- **List results are previews.** Long strings are truncated, including valid metadata trailers. Collection retrieves each full output-item detail and checks evaluation/run IDs, dataset-row identity, version, and markers; the detail resource URI is not the list's ordinal item ID.
- **Transient Python-grader errors are not failed clinical checks.** The service can return `score=0` and `status=completed` together with `sample.error`. The adapter recognizes that error, performs one bounded code-only retry over captured responses, and fails closed if it cannot recover. No agent query is repeated.
- **Terraform tenant pinning.** If the az CLI's default account is in another tenant, set `ARM_TENANT_ID` and `ARM_SUBSCRIPTION_ID` before `azd provision`. Otherwise the providers read with the wrong tenant (403).
- **Eval queue hygiene:** if cloud evals hang, list runs with `evals.list` / `evals.runs.list` and cancel stuck `in_progress` runs; the gate fails closed on missing cloud metrics by design.
- **Quick profile coverage:** it is a demo regression check, not a replacement for the 46-row full release suite. The quick gate requires the exact row IDs and dataset/category identities, both configured built-in judges on answer rows, every applicable clinical code result, and the unchanged deterministic thresholds. Omitted task-adherence and content-safety metrics remain null/not evaluated. A quick green PR check cannot authorize promotion; the merged release run is full.
- **Quick profile native compatibility remains to be verified:** no live evaluation was dispatched for this change. Before presenting a new native result, confirm the official Action accepts the two-judge configuration and exact curated dataset, then inspect the dataset-bound run, retrieved-evidence mapping, token usage, and unchanged production selector. Estimated costs from saved historical tokens are projections only, not measured quick-run cost.
